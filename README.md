# フクマナ LP（Meta広告 → LP → 公式LINE）

フクマナ「経営コース」の潜在顧客に、フクマナ公式LINEを友だち追加してもらうためのLPと広告素材です。

- 公開URL（予定）：https://lp.fukunone.org/
- 成果の指標：LINE友だち追加1件あたりの広告費（CPA）
- ブランドのルールと元素材：`fukunone/fukunone-brand-assets`（非公開）の `BRAND.md`

> このリポジトリは公開（Public）です。パスワードやAPIキーなど、公開してはいけない情報は置かないでください。
> MetaピクセルIDとLINEのURLは、もともとWebページ上で誰でも見られる情報なので置いて問題ありません。

## フォルダ構成

```
ads/                 広告画像と広告文
  ad_copy.md         広告文の一覧（本文・見出し・説明文・CTA）
  a-anxiety/         A案：不安解消型（3サイズ）
  b-knowledge/       B案：知識獲得型（3サイズ）
  c-expert/          C案：専門家型（3サイズ）
  src/               画像の元データ（ad.html）と書き出しスクリプト（render.js）
lp/                  LP本体（このフォルダの中身がそのまま公開される）
  index.html
  assets/css, js, img
  CNAME              独自ドメイン名（lp.fukunone.org）
.github/workflows/pages.yml   GitHub Pages に自動公開する設定
```

## 1. 公開手順（GitHub Pages ＋ 独自ドメイン lp.fukunone.org）

### 手順A：main ブランチを用意する（GitHub）

LPは `main` ブランチ（公開用の本線）から公開されます。いまは作業用ブランチ `claude/tender-allen-1ldxqu` に入っています。

1. https://github.com/fukunone/fukumana-lp を開く。
2. 画面左上のブランチ名のボタン（`claude/tender-allen-1ldxqu` と表示）を押す。
3. 入力欄に `main` と入力し、表示される「**Create branch main from claude/tender-allen-1ldxqu**」を押す。
4. 画面上部の「**Settings**」→ 左メニュー「**General**」→「**Default branch**」の切り替えボタン（⇄）を押し、`main` を選んで「**Update**」→ 確認画面で「**I understand, update the default branch.**」を押す。

### 手順B：GitHub Pages を有効にする（GitHub）

1. 「**Settings**」→ 左メニュー「**Pages**」を開く。
2. 「**Build and deployment**」の「**Source**」で「**GitHub Actions**」を選ぶ。
3. 画面上部の「**Actions**」タブを開き、左の「**Deploy LP to GitHub Pages**」を選ぶ。
4. 右側の「**Run workflow**」→ ブランチが `main` になっていることを確認して、緑の「**Run workflow**」を押す。
5. 1〜2分待ち、緑のチェックマークが付けば公開完了。この時点では `https://fukunone.github.io/fukumana-lp/` で表示を確認できます。

### 手順C：独自ドメインを登録する（GitHub）

1. 「**Settings**」→「**Pages**」を開く。
2. 「**Custom domain**」の入力欄に `lp.fukunone.org` と入力し、「**Save**」を押す。
3. 「DNS check」が始まります。次の手順DでDNSを設定するまではエラー表示のままで問題ありません。

### 手順D：DNSレコードを追加する（Xserver）

1. Xserver の「**サーバーパネル**」にログインする。
2. 「**DNSレコード設定**」を押し、ドメイン一覧から `fukunone.org` を選ぶ。
3. 「**DNSレコード設定を追加**」（追加タブ）を開き、次のとおり入力する。

| 項目 | 入力する内容 |
|---|---|
| ホスト名 | `lp`（入力欄の後ろに `.fukunone.org` と表示されている状態） |
| 種別 | `CNAME` |
| 内容 | `fukunone.github.io` |
| TTL | 変更しない（初期値のまま） |
| 優先度 | 変更しない（初期値のまま） |

4. 「**確認画面へ進む**」→「**追加する**」を押す。
5. DNSレコード一覧に `lp.fukunone.org` ／ `CNAME` ／ `fukunone.github.io` が追加されていることを確認する。

> 注意：すでに `lp.fukunone.org` のAレコードなどがある場合、CNAMEは同じホスト名に併せて登録できません（Xserverの仕様）。先に既存のレコードを確認してください。
> ほかのレコード（メール用のMXなど）は変更しないでください。

### 手順E：「Enforce HTTPS」を有効にする（GitHub）

1. DNSの反映を待つ（数分〜数時間。最大24時間ほどかかることがあります）。
2. 「**Settings**」→「**Pages**」を開き、「Custom domain」の下に「**DNS check successful**」と表示されていることを確認する。
3. 「**Enforce HTTPS**」のチェックボックスにチェックを入れる。
   - チェックボックスが押せない場合は、証明書の発行待ちです。時間をおいてページを再読み込みしてください。
4. `https://lp.fukunone.org/` を開き、LPが表示され、アドレスバーに鍵マークが出ていることを確認する。

### 公開後の更新

`main` ブランチの `lp/` フォルダに変更が入ると、自動で公開し直されます。

## 2. 差し替え箇所（Metaピクセル・LINE URL・流入経路）

差し替えはすべて `lp/index.html` の上のほうにある「**差し替え箇所①**」で行います。

```html
window.FUKUMANA_LP = {
  META_PIXEL_ID: "000000000000000",          ← ① MetaピクセルID
  LINE_URLS: {
    "default": "https://lin.ee/SRA6yFh",     ← ② LINE友だち追加URL（LP専用）
    "a": "",                                  ← ③ 広告A案用の流入経路URL（任意）
    "b": "",                                  ←    広告B案用
    "c": ""                                   ←    広告C案用
  }
};
```

| # | 何を | どこで手に入れるか | 現在の状態 |
|---|---|---|---|
| ① | MetaピクセルID（数字） | Metaイベントマネージャ →「データソース」→ 対象のピクセル（データセット）のID | **仮置き**（`000000000000000`）。仮置きの間はピクセルは読み込まれません |
| ② | LINE友だち追加URL | LINE公式アカウント | **設定済み**（`https://lin.ee/SRA6yFh`） |
| ③ | 広告ごとの流入経路URL | LINE Official Account Manager →「分析」→「友だち」→「流入経路」（流入経路分析）で経路を作成し、発行されたURLを貼る | 空欄（空欄なら②が使われます） |

### 仕組み

- **Metaピクセル**：`<head>` 内の「Metaピクセル（ベースコード）」が、ページ表示時に `PageView` を送ります。
- **Leadイベント**：LINEボタン（`class="js-line"` が付いたボタン。ヘッダー・FV・特典・経営コース・最終CTA・画面下の固定ボタン）を押すと、`lp/assets/js/main.js` の「**差し替え箇所②**」が `fbq('track', 'Lead')` を送ります。どの位置のボタンかも一緒に送られます。
- **流入経路の切り替え**：広告のリンク先URLの末尾に `?utm_content=a`（または `b`／`c`）を付けると、③に入れたURLへ自動で切り替わります。広告ごとの友だち追加数をLINE側で分けて数えられます。
  - 例：`https://lp.fukunone.org/?utm_source=meta&utm_medium=paid&utm_campaign=line_keiei&utm_content=a`
- LINEボタンのURLをHTML内で直接書き換える必要はありません（①〜③の設定が全ボタンに反映されます）。

### CPAの数え方（大事な点）

Metaの管理画面に出る「Lead」は**LPのボタンが押された回数**で、**実際の友だち追加数ではありません**（ボタンを押したあと、LINEの画面で追加せずに離れる人がいるため）。

- 成果の指標（CPA）は、**広告費 ÷ LINEの流入経路分析に出る友だち追加数**で計算してください。
- Meta側の「Lead」は、広告の配信を最適化するための合図として使います。

## 3. Meta広告の初期設定（月1万円の前提）

月1万円は1日あたり約330円です。この金額では配信量が少ないため、**構成をできるだけ1つにまとめる**ことを最優先にします。

| 項目 | 推奨 | 理由 |
|---|---|---|
| キャンペーンの目的 | **リード** | 友だち追加につながる行動（Lead）に向けて配信を最適化するため |
| コンバージョンの場所 | **ウェブサイト** | LPのボタンクリックを計測するため |
| 最適化の目標（パフォーマンスの目標） | **コンバージョン数の最大化**、イベントは **リード（Lead）** | 下の「切り替えの目安」を参照 |
| キャンペーン・広告セットの数 | **1キャンペーン・1広告セット** | 少ない予算を分けると、どれも学習が進まないため |
| 予算 | 広告セットの**1日の予算 330円前後**（または通算予算1万円・期間1か月） | 月1万円を超えないようにするため |
| 配置 | **Advantage+ 配置**（自動） | 3サイズを用意済みなので、フィード・ストーリーズ・リールに自動で出し分けられる |
| 同時に出すクリエイティブ | **3本（A・B・C案を各1本）** | 切り口の違いを比べるため。これ以上増やすと1本あたりの表示が足りなくなる |
| 1本の広告に入れる画像 | 1:1・4:5・9:16の3サイズ（「配置ごとにメディアを設定」で割り当て） | 配置ごとに最適な比率で表示するため |

### ターゲティング（Advantage+ オーディエンスの扱い）

**Advantage+ オーディエンスを使い、「オーディエンス提案」を入れる**ことを推奨します。

- 地域：日本
- 年齢の下限：18歳（これは必ず守られる設定）
- オーディエンス提案（あくまで「この辺りから探してほしい」という目安で、配信がこの範囲に限定されるわけではありません）
  - 年齢：20〜39歳
  - 性別：男性
  - 興味・関心の例：起業、スモールビジネス、社会福祉、介護、保育、障害福祉【要確認：管理画面で実際に選べる項目名】

理由：予算が小さいと、手動で対象を狭めたときに配信できる人数が足りず、表示単価が上がりやすいためです。まずはMetaの自動配信に任せ、結果を見て判断します。

**2週間後の見直しポイント**

- 管理画面の「内訳」→「年齢と性別」で配信先を確認する。想定（20〜30代男性）から大きく外れ、かつ友だち追加につながっていない場合は、「**元のオーディエンスオプションに切り替え**」を選び、年齢20〜39歳・男性・興味関心を固定する。
- ターゲット層の内外にかかわらず、友だち追加が取れている層は止めない（成果の指標はCPAのため）。

### 切り替えの目安

Metaの配信は、最適化イベントが週に一定数（一般に約50件と言われます【要確認：Meta公式ヘルプで未確認】）たまると安定します。月1万円ではこの件数に届かない可能性が高いです。

- 開始から2週間で **Lead（ボタンクリック）が10件未満** の場合：パフォーマンスの目標を「**ランディングページビュー数の最大化**」（目的：トラフィック）に切り替え、まずLPに来る人を増やす。
- クリエイティブは、2週間たってから比べる。表示回数が極端に少ないものは判断しない。成績のよい1本を残し、同じ切り口で画像違いを1本足す。
- 配信開始後の最初の1〜2週間は、予算・ターゲット・広告を細かく変更しない（変更のたびに学習がやり直しになるため）。

### 出稿前のチェック

- [ ] MetaピクセルIDを差し替えた（上の①）
- [ ] Metaイベントマネージャの「イベントのテスト」で、LP表示時に PageView、LINEボタンを押したときに Lead が届くことを確認した
- [ ] 広告のリンク先URLに `utm_content=a／b／c` を付けた
- [ ] スマホで広告→LP→LINE友だち追加→「講義を視聴する」送信まで、実際に通して試した
